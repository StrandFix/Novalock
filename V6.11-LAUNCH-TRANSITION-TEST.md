# Novalock V6.11 — Cocoon launch-transition image experiment

V6.10 correctly indexed the selected Cocoon artwork folder, but Retroid Pocket
Nova reported only fullscreen accessibility focus nodes, so no selected card
could be captured. This experiment adds an independent image path while keeping
the existing emulator-title, focused-card, and live-gameplay screenshot paths.

## Operation

1. Novalock's accessibility service observes, but does **not consume**, the
   controller's confirm key while Cocoon is in the foreground. An Android
   `TYPE_VIEW_CLICKED` event can trigger the same path for touch input; a
   direct Cocoon-to-emulator window switch is a secondary trigger if the
   device does not expose controller keys.
2. About 90 ms after the launch input, it requests a single screenshot using
   the existing accessibility screenshot capability. The image stays in RAM.
3. A strict detector rejects normal Cocoon HOME screens and screenshots that do
   not contain an isolated central image on a predominantly dark background.
4. Only a unique, high-confidence match against locally indexed images may be
   associated with the subsequent emulator app. All other cases use the
   original live screenshot fallback. No ROM interception, Cocoon patch or
   per-game setup is required.

## Device test

1. Install the V6.11 test build **beside** V6.10. GitHub Actions uses a fresh
   debug signing key, so it cannot replace an installed V6.10 signed by a
   different runner. V6.11 has its own test package and settings.
2. Turn off V6.10's active lock service and accessibility permission while
   testing. Enable the V6.11 accessibility service and its other permissions.
   If it was already enabled, disable and re-enable it so Android recognizes
   the new key-event capability.
3. Choose Cocoon Icon or Cocoon Hero; grant the existing artwork folder and
   refresh the index until it says `Card index ready`.
4. Start a game in Cocoon with the normal controller confirm button, wait for
   the emulator to open, then lock and unlock once.
5. Copy artwork diagnostics. Note:
   - `Launch-confirmation inputs` — whether Android delivered the button.
   - `Launch-transition screenshot` — whether the timed frame was captured,
     contained an isolated icon, and had a unique artwork match.
   - `Assigned title` / `Loaded image` — whether the match bound to the emulator.

This is a device experiment. If the transition lasts less than a screenshot
can capture, the matcher will safely reject it; a timed one-shot cannot prove
the frame exists. An eventual video-frame buffer would require a different
screen-capture permission model and is **not** silently enabled here.

No changes are needed in Cocoon or any emulator. Switch back to Live screenshot
in Novalock to disable the experiment.
